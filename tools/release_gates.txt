# The release and landing gates: the one list.
#
# Read by tools/release.py (before it tags), by tools/check_release_tsan.py
# (Release Check's tag-push second check), by tools/land.py (before it merges
# a pull request) and by tools/check_release_gates.py (lint: every workflow and
# job named here exists). docs/RELEASING.md and docs/branch-protection.md
# describe it; they do not repeat it.
#
# One gate per line, five fields separated by " | ", then the reason:
#   workflow | job | kind | from | events | reason
#
# workflow  a file under .github/workflows
# job       "-" for a whole-run gate; otherwise a display name as the Actions
#           API reports it ("<ref>" stands for the run's own head branch;
#           a skipped matrix job is reported under its unexpanded template)
# kind      run          the newest completed run on the commit concluded success
#           run-if-ran   the same, when the workflow ran on the commit at all
#           jobs         the newest completed run on the commit: every job success,
#                        except a job named by a `skip` row (and none missing)
#           jobs-if-ran  the same, when the workflow ran on the commit at all
#           job          the named job concluded success in the newest completed
#                        run on the commit that has it
#           skip         the named job may be `skipped` in a `jobs` gate (its own
#                        `if:` leaves it out of these events); success also passes
#           full         the named job of a `jobs` gate is FULL tier: for a point
#                        release and for tools/land.py (without --full) it is
#                        printed with its result and does not gate, and the
#                        workflow's `run` gate is judged job by job; a minor,
#                        major or pre-release holds it like any job (owner,
#                        2026-11-13: point releases have light tests only)
#           tlc-rerun    a `TLC re-run full` job success on the exact commit, or
#                        every `TLC re-run slice K/N` (K = 0..N-1) success in
#                        scheduled runs of the last N days on ancestors of the commit
#           tag          a job of the run the release tag's push starts; the
#                        release tool waits for it and publishes only on success
# from      the first version the gate is in force for (earlier versions are
#           judged by the gates in force then; the output names the rest)
# events    push          the push to main of the commit (per-commit tier)
#           pull_request  the pull request's head commit (tools/land.py)
#           nightly       any run whose head is the commit (schedule or dispatch);
#                         minor-only: from v1.1.8 a point release (vX.Y.Z, Z
#                         not 0, no pre-release suffix) skips these rows, printed
#                         as MINOR ONLY; a pre-release or a
#                         minor or major release (Z = 0) is judged by them
#                         (owner, 2026-11-13: point releases have fast tests only)
#           tag           the push of the release tag
#
# The run, nightly-tier and tag gates in force from v1.0.0-preview-6 are the
# ones docs/RELEASING.md and Release Check required then; the rest are new in
# v1.1.8 (2026-11-12: every job success, Nightly CI every job, the TLC re-run
# evidence, MemorySanitizer, the tag run's final job).
