# tools/msan_known.txt: the known MemorySanitizer findings for the portable
# unit suite. A finding is the top frame of one MemorySanitizer warning, in
# the form the gate prints: function and source location, with a binary-only
# frame written as `(bin/test)` and a C++ library frame written under
# `include/c++/`. A warning whose top frame is absent here fails
# `bash tools/run_msan.sh`. The gate passes when the run is clean or every
# finding is listed.
#
# The list is empty: the gate runs clean with clang 18.1.3 and 21.1.8. The
# findings it used to hold were blind spots, each fixed at its cause:
#
# - sodium's raw syscall(SYS_getrandom) fill and libc's explicit_bzero wipe
#   wrote memory MSan cannot see; under MSan the generator's
#   SANITIZER_ADAPTATIONS unpoison exactly the bytes each one wrote
#   (tools/generate_sodium.py, sodium/README.md).
# - the system libstdc++ is not instrumented; the gate links the
#   MSan-instrumented libc++ (tools/build_msan_libcxx.sh).
# - three tests compared or scanned bytes nothing had written (a region's
#   unused memory, a caller's arena block, a reassembly set's staging); each
#   now starts those bytes zeroed.
#
# A new entry is a finding with a written cause, never a line to make the
# gate green: fix the cause where it can be fixed.
