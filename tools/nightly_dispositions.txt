# The owned reds of the scheduled workflows (tools/check_nightly_dispositions.py,
# .github/workflows/nightly-watch.yml). One row per job that is not green, tab
# separated, five fields:
#
# <workflow file>	<job name prefix>	<owner>	<YYYY-MM-DD>	<cause>
#
# owner: `#<open pull request that fixes it>`, or a lower-case name when no
# pull request is open (`glenn` is the default owner; `owner-needed` is refused).
# date: the day the row was last checked against the job's real state; a row
# more than 14 days old whose job is still red fails the watch (STALE), so a
# row is re-confirmed or the job fixed. A cause beginning `expected-skip:`
# declares that the job's `skipped` conclusion is green.
#
# A job that is not green with no row fails the watch (NEW-RED for a failure,
# NO-VERDICT for cancelled, timed out, skipped or unfinished); a row whose job
# is green, or whose pull request is merged or closed while the job is still
# red, fails it too (STALE). Remove a row in the pull request that turns its
# job green.
#

# scheduled run of each workflow on main. 17 named jobs that are green now;

# on s390x; outage_pair CONNECTION_TIMED_OUT), and their pull requests (#722,
# #735, #767, #775) are merged or closed. All 21 were removed; today's reds are
