### 1.2 Synthesis and Epistemic Merge Rules

1. **Complete Union of Ideas (`## 2 Idea ledger`):** Every distinct architectural proposal, protocol adaptation, transport mechanism, client packaging option, and optimization across `emma`, `aurora`, and `stella` is assigned a stable union identifier (`U1`–`U56`), traced to the exact `file:line` where each input proposed or evaluated it, and given an explicit disposition (`carried into §4`, `carried into §6 as experiment E#`, or `parked with reason`).
2. **Explicit Preservation of Agreements and Open Disagreements (`## 3 Agreements and disagreements`):** Where all three inputs independently converge on the same conclusion, `§3.1` records the consensus and its supporting citations. Where two or more inputs diverge—on token admission boundaries, handshake cookie splicing, inbound/outbound QUIC MTU clamping, Emscripten WASM vs. TypeScript client primacy, WebSocket head-of-line mitigations, or Edge/CanIUse version figures—`§3.2` preserves each input's full reasoning without papering over differences by majority vote, and links the exact experiment in `§6` that settles the question empirically.
3. **Complete Union of Experiments (`## 6 Ranked R&D plan`) and Sources (`## 7 Sources`):** All experiments across `emma` (`E1`–`E12`), `aurora` (`E1`–`E12`), and `stella` (`E1`–`E14`) are merged, de-duplicated into 18 concrete experiments (`E1`–`E18`), and re-ranked by `decision value / cost in worker-days`, keeping explicit overturn criteria for every core recommendation. All external and repository sources across the three inputs are merged and de-duplicated in `§7` (`[R1]`–`[R8]` and `[S1]`–`[S80]`).
4. **Strict Claim Labeling (`SOURCED`, `ESTIMATED`, `OPINION`, `UNVERIFIED`):** Every factual claim in Sections 3, 4, and 5 carries an inline epistemic tag: `SOURCED` (verified directly against repository code/specs or dated external standards/datasets), `ESTIMATED` (back-of-the-envelope calculation with explicit arithmetic), or `OPINION` (engineering judgment grounded in sourced facts). No unmeasured benchmark, bundle size, or global traffic share is presented as measured fact; all unmeasured quantities remain marked `ESTIMATED` or `UNVERIFIED`.

## 3 Agreements and disagreements

### 3.1 Where the Inputs Agree

Across all seven research topics, `emma`, `aurora`, and `stella` independently reached the same conclusions on the following seven foundational pillars:

1. **Primary Transport — `WebTransport` over HTTP/3 (`QUIC DATAGRAM`):**
   * All three inputs select **WebTransport over HTTP/3** (`[SOURCED: S1, S4, S5, S33, S35]`) as the primary browser transport (`[SOURCED: emma.md:6, aurora.md:5, stella.md:5]`).
   * **Shared evidence:** WebTransport provides true unreliable, unordered datagrams at the QUIC framing layer (`RFC 9221` `[SOURCED: S5]`, `RFC 9297` `[SOURCED: S4]`), completes transport + TLS 1.3 + HTTP/3 setup in **1 RTT** (`[SOURCED: S33, S35]`), supports pinning short-lived ($\le 14$-day) self-signed ECDSA P-256 certificates via `serverCertificateHashes` (`[SOURCED: S1 §6.9, S16]`), and achieved support across all three major browser engines when **Safari 26.4** (macOS and iOS) shipped WebTransport in March 2026 alongside **Chrome 97+**, **Edge 97+/98+**, and **Firefox 114+** (`[SOURCED: S9, S54, S60, S76]`).
2. **Mandatory Three-Tier Transport Cascade (`WebTransport` $\rightarrow$ `WebRTC` $\rightarrow$ `WebSocket`):**
   * All three inputs agree that no single browser API provides 100% player reach with unreliable datagrams (`[OPINION]` grounded in `[SOURCED: emma.md:6, 398; aurora.md:5, 160; stella.md:5, 13]`).
   * **Shared evidence:** Devices on macOS/iOS $\le 26.3$ (where all iOS browsers outside EU alternative-engine entitlements use system WebKit `WKWebView` `[SOURCED: S54, S60, S79]`) lack `WebTransport` and require **WebRTC `RTCDataChannel`** (`ordered: false, maxRetransmits: 0`, supported in Chrome 30+, Firefox 22+/62+, Safari/iOS 11+ `[SOURCED: S2, S6, S10, S56]`). Enterprise, campus, and school networks that block all outbound UDP require **WebSockets (`wss://`) over TLS/TCP port 443** (`[SOURCED: S3, S8, S11, S58]`).
3. **Server Architecture — Co-Located / Sidecar Browser Gateway Allocating One Local UDP Socket per Session (`Topology A`):**
   * All three inputs recommend deploying a **co-located sidecar Browser Gateway** that terminates the outer browser transport (HTTP/3, DTLS/SCTP, or TLS/TCP) and allocates **one dedicated local UDP socket (`127.0.0.1:ephemeral_port`) per browser session** toward the unmodified native `rocketnet` server (`[OPINION]` grounded in `[SOURCED: emma.md:7, 103-110; aurora.md:5, 72-80; stella.md:5, 45-50]`).
   * **Shared evidence:** `STANDARD.md` (`line 348`, `[SOURCED: R1]`) establishes that *"the client address is the connection identity"*, and the native server (`sdk/rocketnet_server_transport.cpp`, `DRIVERS.md` `[SOURCED: R4]`) is engineered around a zero-allocation UDP loop using Linux `AF_XDP`, `UDP_SEGMENT` (`GSO`), `recvmmsg`/`sendmmsg`, and macOS `sendmsg_x`/`recvmsg_x` with vendored `sodium/sodium.c` as its sole library dependency (`[SOURCED: R1, R4]`). A sidecar per-session UDP gateway preserves native XDP/GSO fast paths on the external NIC and avoids pulling OpenSSL/BoringSSL, SCTP (`usrsctp`), or Rust/Go runtimes into `librocketnet` (`[OPINION]`).
4. **End-to-End Inner RocketNet Encryption (`ChaCha20-Poly1305` IETF AEAD) and Replay Protection:**
   * All three inputs agree that RocketNet's inner `ChaCha20-Poly1305` IETF encryption (`[SOURCED: R1, STANDARD.md:38-44, 1285-1399]`), 64-bit sequence numbers, ack blocks, and 4096-packet replay window (`[SOURCED: R1, STANDARD.md:1533-1703]`) must remain **end-to-end between the browser client and the native server** (`[OPINION]` grounded in `[SOURCED: emma.md:8, 154-168; aurora.md:5, 88-93; stella.md:5, 62-63]`).
   * **Shared evidence:** The inner RocketNet wire envelope (`6 B` prefilter + `4 B` sequence + `16 B` Poly1305 tag = `26 B`, plus `7 B` minimum ack block `[SOURCED: R1, STANDARD.md:625-698]`) adds only `2.11%–2.68%` byte overhead on a 1232-byte packet (`26 / 1232 = 2.11%` `[ESTIMATED]`) and microsecond-scale WASM CPU cost, while keeping the gateway a **zero-trust ciphertext relay** that never holds `server_secret_key` (`[SOURCED: R1, STANDARD.md:176-216, 792-822]`).
5. **Browser Cryptographic Primitives (`libsodium` in WASM vs. `WebCrypto`):**
   * All three inputs verify that while W3C Web Cryptography Level 2 (`[SOURCED: S20, S53, S57]`) now includes `Ed25519` (`Chrome 137+`, `Firefox 129+`, `Safari 17+`) and `X25519` (`Chrome 133+`, `Firefox 130+`, `Safari 17+`) — correcting the older assumption that `Ed25519` is absent from `SubtleCrypto` — **`WebCrypto` still has zero support for `ChaCha20-Poly1305` IETF, `BLAKE2b`, or `SipHash-2-4`** (`[SOURCED: S53, S57]`), and the RocketNet client **never verifies `Ed25519` signatures anyway** (`[SOURCED: R1, STANDARD.md:180-185, 890-893]`). Therefore, every browser client (`Family A` or `Family B`) must use WASM `libsodium` (`sodium/sodium.c` or `libsodium.js` `[SOURCED: S72, S73]`) (`[SOURCED: emma.md:260-271; aurora.md:107-109; stella.md:85, 99]`).
6. **Zero Mandatory `SharedArrayBuffer` / `COOP`+`COEP` Requirement in Production:**
   * All three inputs agree that the shipping browser client must not require `SharedArrayBuffer` (`Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`), because COOP/COEP breaks cross-origin ads, OAuth popups, payment iframes, and embedded portals, and `SharedArrayBuffer` is completely unsupported in Android `WebView` (`webview_android: false` `[SOURCED: S59]`) (`[SOURCED: emma.md:250; aurora.md:121, 151; stella.md:90, 92]`).
7. **Disqualification of `libwebrtc` on the Server Side:**
   * All three inputs reject Google's monolithic `libwebrtc` (`[SOURCED: S75]`) for server or gateway use due to its multi-gigabyte Chromium build system (`depot_tools`, `gn`, `ninja`, BoringSSL/Abseil linkage) and media-conferencing thread overhead, preferring `paullouisageneau/libdatachannel` (`C++17`, `MPL-2.0` `[SOURCED: S63]`), `webrtc-rs` (`Rust`, `Apache-2.0`/`MIT` `[SOURCED: S64]`), or `pion/webrtc` (`Go`, `MIT` `[SOURCED: S65]`) (`[SOURCED: emma.md:118-121; aurora.md:59-65; stella.md:56]`).

### 3.2 Where the Inputs Disagree (Preserved Open Questions and Settling Experiments)

Where the three inputs differed in analysis, mechanism design, or data interpretation, both sides are preserved in full below together with the specific experiment in `## 6 Ranked R&D plan` that resolves the disagreement:

1. **Connect Token (`768 B`) vs. `Type 0 Connection Request` (`710 B`) Wire Boundary & Gateway Admission (`stella` vs. `emma` and `aurora`):**
   * **`emma` (`emma.md:173-185`) and `aurora` (`aurora.md:89-90`):** Propose stateless gateway admission using the public `backend_public_key` (`32 B`) to verify the `Ed25519` signature (`64 B`) over the `576 B` `signed connect data` (`STANDARD.md:824-893` `[SOURCED: R1]`) before allocating a local UDP socket. In `aurora.md:89-90` (and as an optional URL/stream bootstrap in `emma.md:197`), the browser presents the Connect Token during the WebTransport/WebSocket handshake.
   * **`stella` (`stella.md:64, 152`):** Discovers from `STANDARD.md` (`lines 824–893` `[SOURCED: R1]`) and `sdk/rocketnet_connect_token.cpp` (`[SOURCED: R6]`) that the raw **768-byte `rocketnet_connect_token`** contains the two 32-byte token keys (`client_to_server_key` and `server_to_client_key`) **in cleartext at bytes `640..703`** (for the client's own local use), whereas the **710-byte `Type 0 Connection Request`** packet transmitted on the wire (`6 B` header + `24 B` cookie + `32 B` `client_eph_pk` + `8 B` `handshake_salt` + `576 B` `signed connect data` + `64 B` `Ed25519 signature` `[SOURCED: R1, STANDARD.md:1204-1225]`) strips bytes `640..768` and carries the session keys **only inside the 432-byte `sealed_private_block` encrypted to `server_public_key`**! Therefore, if a browser sends the full 768-byte Connect Token to an untrusted gateway, it leaks `client_to_server_key` and `server_to_client_key` (`stella.md:64`). `stella.md:152` further argues that the gateway should either inspect only the 710-byte `Type 0` packet (`or its 640-byte signed slice`) and keep admission **provisional** until the native server replies with `Type 2` / `Type 4`.
   * **Synthesis & Settling Experiment:** `stella`'s finding (`U27`) is a critical security invariant verified directly in `STANDARD.md:870-893` and `sdk/rocketnet_connect_token.cpp` (`[SOURCED: R1, R6]`): **the browser must never transmit bytes `640..768` of the 768-byte Connect Token over the network**. Combining `emma.md:175-185` (verifying `Ed25519` over the 640-byte signed slice inside the 710-byte `Type 0` packet) with `stella.md:152` (two-phase provisional socket commitment until native `Type 2`/`Type 4` arrives) gives both zero-secret edge DoS protection and zero key leakage (`[OPINION]`). Settled by **`E4`** and **`E17`**.
2. **Handshake RTT Count (`CLAUDE.md` 2-RTT vs. `STANDARD.md` 3-RTT) and Gateway Loopback Cookie Splicing (`emma` & `aurora` vs. `stella`):**
   * **`stella` (`stella.md:78, 206`):** Points out a documentation discrepancy in the repository: `CLAUDE.md` (`line 71` `[SOURCED: R5]`) describes an "address-validated two-RTT handshake", whereas `STANDARD.md` (`lines 1136–1184` `[SOURCED: R1]`) and `sdk/rocketnet_server_protocol.cpp` (`[SOURCED: R8]`) execute a **3-RTT cold handshake** (`RTT 1: Type 0 -> Type 7 Cookie`; `RTT 2: Type 0+Cookie -> Type 2 Challenge`; `RTT 3: Type 3 Response -> Type 4 Keep-Alive`). `stella.md:78` recommends preserving the native server's cookie gate end-to-end across the browser link so the gateway does not weaken anti-spoofing or slot admission.
   * **`emma` (`emma.md:189-198, 409-410`) and `aurora` (`aurora.md:94-97, 165`):** Also identify the 3-RTT cold handshake in `STANDARD.md:1136-1184` (`[SOURCED: R1]`), and note that because the gateway has already validated the browser's return address via QUIC (`1 RTT`), TCP+TLS (`2 RTTs`), or ICE+DTLS (`5 RTTs`) **and** because bytes `6..30` (`return_cookie`) of the 710-byte `Type 0 Connection Request` are outside the `Ed25519` signature (`[SOURCED: R1, STANDARD.md:1204-1225]`), the co-located gateway can perform the `Type 0 (zero cookie)` $\rightarrow$ `Type 7 (38B cookie)` $\rightarrow$ `Type 0 (spliced cookie)` exchange against the native server over `127.0.0.1` in `< 150 us` (`[ESTIMATED]`), saving 1 full wide-area RTT (`20–100 ms`) with **zero modifications to `STANDARD.md` or the native server** (`[OPINION]`).
   * **Settling Experiment:** Tested directly in **`E4`** (measuring wide-area handshake latency savings and testing gateway provisional rate limits under spoof/flood load in **`E17`**).
3. **Handling the 1232-Byte Packet Budget vs. WebTransport's 1171–1200 B Initial QUIC Datagram Floor (`emma` vs. `aurora` vs. `stella`):**
   * **All three inputs (`emma.md:35, 200-213; aurora.md:29, 98-100; stella.md:17, 66, 153`):** Agree that RocketNet's default `1232 B` UDP packet ceiling (`1192 B` payload + `33–40 B` wire overhead `[SOURCED: R1, STANDARD.md:295-296, 625-698; R3, sdk/rocketnet.h:411-434]`) collides with QUIC v1's `1200 B` minimum initial UDP payload (`RFC 9000 §14` `[SOURCED: S35]`) once outer QUIC short-header + AEAD tag + HTTP/3 `DATAGRAM` framing (`~29–48 B`) is subtracted (`maxDatagramSize` floor of `~1152–1171 B` `[ESTIMATED]`).
   * **`aurora` (`aurora.md:99-100`):** Proposes capping browser outbound payloads to `1140 B` (`~1180 B` RocketNet packet) and falling back from WebTransport to WebRTC if `maxDatagramSize < 1232 B`.
   * **`emma` (`emma.md:210-212`):** Proposes clamping `max_payload_bytes` to `1120 B` (`1153 B` RocketNet packet, fitting inside the `1171 B` floor on 100% of QUIC v1 paths) **and**, if an unmodified native server emits a `1225–1232 B` packet toward the gateway before QUIC PMTUD (`RFC 8899` `[SOURCED: S78]`) grows `maxDatagramSize`, forwarding that oversized packet over a **one-shot WebTransport unidirectional stream** so zero packets are dropped.
   * **`stella` (`stella.md:66, 153`):** Emphasizes the **asymmetric MTU trap**: clamping only the browser's outbound send budget leaves the unmodified native server sending `1225–1232 B` `Packet Type 5` / `Type 9` fragments back to the gateway, which the gateway's WebTransport stack will drop if the browser leg's `maxDatagramSize` is `< 1232 B`. `stella` proposes negotiating a bidirectional conservative MTU profile (`1024–1120 B`) at session setup (`U35`).
   * **Settling Experiment:** Tested in **`E3`** (observing real `maxDatagramSize` across Chrome, Firefox, and Safari 26.4) and **`E7`** (testing bidirectional MTU clamping and unidirectional stream spillover on constrained-MTU paths).
4. **Primary Browser Client Implementation: Emscripten C++ WASM (`Family A`) vs. Pure TypeScript + WASM `libsodium.js` (`Family B`) (`emma` & `stella` vs. `aurora`):**

   * **`aurora` (`aurora.md:5, 111-125`):** Recommends **Family B (pure TypeScript state machine + `libsodium.js` WASM)** for web-native JS/TS games (`estimating ~65 KB Brotli vs. ~145 KB Brotli for Family A`) while keeping Family A for Unity/Godot/Bevy engine targets (`[OPINION]`).

5. **WebSocket Head-of-Line (HoL) Blocking Mitigations: Multi-Socket Striping ($K=3$) and Unreliable Frame Dropping (`emma` & `aurora` vs. `stella`):**
   * **`aurora` (`aurora.md:52, 169`):** Proposes inspecting the RocketNet packet type and `CHANNELS.md` header at the gateway to drop stale unreliable `Packet Type 5` payloads when a WebSocket TCP send buffer backs up.
   * **`stella` (`stella.md:23, 73, 156`):** Proves from `STANDARD.md` (`lines 1285–1399` `[SOURCED: R1]`) that **an untrusted gateway cannot inspect `docs/CHANNELS.md` reliability metadata inside `Packet Type 5`** because the entire `Type 5` payload (and ack block) is encrypted under `ChaCha20-Poly1305` with `RKTNSESC`/`RKTNSESS` keys held only by the browser and native server (`[SOURCED: R1]`).
   * **`emma` (`emma.md:65-66, 415-416`):** Avoids ciphertext inspection by proposing (a) **$K=3$ parallel striped `wss://` connections** bound to the same gateway local UDP session socket (`dispatching each packet to a lane with bufferedAmount === 0`, relying on RocketNet's existing 64-bit sequence number and 4096-packet replay bitmap to reorder packets across TCP lanes `[SOURCED: R1, STANDARD.md:1533-1703]`), and (b) shedding queues using outer socket `bufferedAmount` / `TCP_NOTSENT_LOWAT`.
   * **Settling Experiment:** Tested in **`E8`** (quantifying single-WebSocket vs. $K=3$ striped WebSocket vs. outer-priority-tagged queue shedding under `0, 1, 2, 5, 10%` `tc netem` loss).
6. **Gateway Implementation Language (`C/C++/Rust` vs. `Go` Sidecar) (`emma` & `stella` vs. `aurora`):**
   * **`emma` (`emma.md:116-128`) and `stella` (`stella.md:56-59`):** Recommend C/C++/Rust sans-I/O libraries (`ngtcp2` or `cloudflare/quiche` for HTTP/3 WebTransport, `libdatachannel` or `webrtc-rs` for WebRTC, `uWebSockets` for WebSockets) so the gateway has zero garbage-collection pauses (`[OPINION]`).
   * **`aurora` (`aurora.md:61, 67-69`):** Highlights Go (`pion/webrtc` + `quic-go`/`webtransport-go`) as a zero-C++-build-burden sidecar option for fast iteration while agreeing that C++/Rust wins on tail latency and memory per client (`[OPINION]`).
   * **Settling Experiment:** Tested in **`E10`** (2,500-client 60 Hz load shootout comparing `ngtcp2`/`quiche`, `libdatachannel`, `pion/webrtc`, and `uWebSockets` on CPU, RSS memory/client, and $p_{99.9}$ relay latency).
7. **Edge Initial `WebTransport` Version (`97` vs. `98`) and Global Share Figures (`aurora` vs. `emma` & `stella`):**
   * **`aurora` (`aurora.md:28-35, 140-148`):** Reports Edge `97+` and cites `caniuse` global share totals (`91.64%` WebTransport, `96.26%` WebRTC DataChannel, `99.35%` WebSockets).
   * **`emma` (`emma.md:21, 368, 394-398`) and `stella` (`stella.md:131, 141-143, 265`):** Document that MDN `browser-compat-data` (`api/WebTransport.json` `[SOURCED: S54]`) lists `Edge 97` while `Fyrd/caniuse` (`features-json/webtransport.json` `[SOURCED: S60]`) lists `Edge 98`, and that raw `Fyrd/caniuse` feature JSON files store `usage_perc_y: null` (`computing global share dynamically in the browser UI via external StatCounter tables`), so exact player-weighted reach percentages remain `UNVERIFIED` until measured on real game telemetry. Both version numbers (`97/98`) and the `UNVERIFIED` status of global share percentages are preserved in `§4.6`.

## 4 Merged design

### 4.1 Topic 1 — Transports

The browser transport layer uses a **three-tier Happy-Eyeballs cascade (`WebTransport` $\rightarrow$ `WebRTC DataChannel` $\rightarrow$ `WebSockets`)** (`[OPINION]` grounded in `[SOURCED: S1–S11, S33–S45]`):

| :--- | :--- | :--- | :--- | :--- |

* **Critical `WebTransport` Implementation Requirements (`[SOURCED: S1, S16, S17, S54, S55]`):**
  1. **Writer API Normalization (`U4`):** Because Safari 26.4 implements `wt.datagrams.createWritable()` (`26.4`) and sets `wt.datagrams.writable` to `false`, whereas Chrome `97–157` implements `wt.datagrams.writable` and sets `createWritable()` to `false` (`Firefox 155+` supports both `[SOURCED: S55]`), the client must acquire its `WritableStream` via `const writable = typeof wt.datagrams.createWritable === "function" ? wt.datagrams.createWritable() : wt.datagrams.writable;` (`[OPINION]` grounded in `[SOURCED: S1 §15.10, S55]`).
  2. **Ephemeral Certificate Pinning (`U5`):** When using `serverCertificateHashes`, the gateway certificate **must** use `ECDSA` with `secp256r1` (`NIST P-256`; RSA is forbidden by `W3C WebTransport §6.9`), have a validity period of **at most 14 days (2 weeks)**, and be opened with `allowPooling: false` (`[SOURCED: S1 §6.2, §6.9; S16]`).
  3. **HTTP/2 Fallback Exclusion (`U16`):** While Safari 26.4 and the W3C spec define an HTTP/2 capsule fallback for WebTransport (`[SOURCED: S1, S4, S76]`), HTTP/2 runs over a single TCP connection and suffers full TCP head-of-line blocking; on UDP-blocked networks, explicit Tier-3 WebSockets (or $K=3$ striped WebSockets) provides direct control over `bufferedAmount` and socket striping (`[OPINION]`).
* **Critical `WebRTC` Implementation Requirements (`[SOURCED: S2, S6, S7, S38, S56]`):**
  1. **Unordered Zero-Retransmit Configuration (`U7`, `U8`):** Configure `pc.createDataChannel("rocketnet", { ordered: false, maxRetransmits: 0, negotiated: true, id: 0 })` (`[SOURCED: S2, S6, S7, S19]`).
  2. **Server-Side `ICE-Lite` + `UDP-Mux` (`U9`):** The gateway runs `ICE-Lite` (`RFC 8445 §2.2` `[SOURCED: S38]`) and multiplexes all WebRTC sessions onto a single public UDP port (`UDP-Mux` `[SOURCED: S63, S64, S65]`). The browser posts its SDP offer to the gateway over HTTPS and receives the SDP answer containing the gateway's `host` candidate and DTLS `a=fingerprint:sha-256` (`[SOURCED: S41]`), avoiding external STUN servers (`iceServers: []`) unless TURN relay fallback (`U10`, `RFC 8656` `[SOURCED: S40]`) is required.
* **Critical `WebSocket` Implementation Requirements (`[SOURCED: S3, S8]`):**
  1. **Socket Tuning (`U11`, `U14`):** Set `binaryType = "arraybuffer"` on the browser `WebSocket` (`[SOURCED: S3, S24]`), disable `permessage-deflate` (`U11`), and set `TCP_NODELAY`, `TCP_QUICKACK`, `TCP_NOTSENT_LOWAT`, and `TCP_CONGESTION = "bbr"` on the Linux gateway (`[OPINION]`).
  2. **Queue Shedding & Multi-Socket Striping (`U12`, `U13`, `U52`):** Because `Packet Type 5` payloads are encrypted end-to-end (`STANDARD.md:1285-1399` `[SOURCED: R1]`), the gateway cannot inspect inner `CHANNELS.md` reliability flags (`stella.md:73, 156`). Queue shedding therefore acts at the browser sender (where reliability is known before encryption, checking `ws.bufferedAmount`) and/or via $K=3$ striped WebSocket connections (`emma.md:65, 415`), tested in `E8` (`[OPINION]`).

### 4.2 Topic 2 — Server Side

#### A. Gateway vs. In-Process Embedding Architecture (`U18`–`U21`, `U25`)

```
[ Browser Client (WASM / TS) ]
       |  Tier 1: WebTransport (HTTP/3 QUIC Datagram, UDP/443)
       |  Tier 2: WebRTC DataChannel (ICE-Lite + DTLS + SCTP, UDP/4443)
       |  Tier 3: WebSocket (TLS 1.3 + TCP/443, K=1 or K=3 striped)
       v
[ Co-Located Browser Gateway (Same Physical Host) ]
  - Verifies 64B Ed25519 signature on 576B signed block of 710B Type 0 Request
  - Allocates 1 local UDP socket per browser session: bind(127.0.0.1:0) -> port_i
  - Forwards raw inner RocketNet ciphertext datagrams verbatim (zero shared secrets)
       |
       |  Loopback UDP (127.0.0.1:port_i <-> 127.0.0.1:40000) [Topology A, Default]
       |  OR Shared-Memory Ring Driver (rocketnet_shm_driver) [Topology B, E9 Option]
       v
[ Unmodified Native C++ RocketNet Server (librocketnet) ]  <-- Direct UDP (AF_XDP / GSO)
                                                               from Native Desktop/Console Clients
```

* **Why Topology A (Co-Located Per-Session UDP Gateway) is the Default (`[OPINION]` grounded in `[SOURCED: R1, R3, R4]`):**
  1. **Preserves `STANDARD.md:348` Identity Invariant (`[SOURCED: R1]`):** Every browser session $i$ receives its own local UDP socket `udp_fd[i]` bound to an ephemeral port on `127.0.0.1` (`or 127.0.0.1..127.0.0.16` if $> 32{,}768$ browser clients connect to one host, `U19`). The native server sees a distinct, stable `(127.0.0.1, port_i)` `rocketnet_address_t` for the entire lifetime of the session (`[SOURCED: R1, STANDARD.md:342-392]`).
  2. **Preserves Native `AF_XDP` and `GSO` Fast Paths (`U21`, `[SOURCED: R4, DRIVERS.md]`):** Native UDP clients continue hitting the external NIC via `AF_XDP` or `GSO`/`recvmmsg` untouched. When a single server instance serves both external `AF_XDP` clients and co-located browser gateway clients, the gateway couples via a `veth` interface or a composite `rocketnet_server_driver_operations_t` driver (`U20`, `[SOURCED: R4, sdk/rocketnet_driver.h:35-70]`).
  3. **Zero Third-Party TLS/QUIC/SCTP Bloat in `librocketnet` (`[SOURCED: R1, R3]`):** `librocketnet` keeps vendored `sodium/sodium.c` (`ISC` license `[SOURCED: S73]`) as its sole dependency.
  4. **Seamless Outer IP Migration (`U50`):** When a mobile browser switches from Wi-Fi to 5G cellular and migrates its outer QUIC connection (`RFC 9000 §9` `[SOURCED: S35]`) or rebinds its gateway session, `udp_fd[i]`'s local port never changes, so the native server never drops the session (`[OPINION]`).

### 4.3 Topic 3 — Protocol Mapping

1. **End-to-End RocketNet Wire Protocol (`U26`):**
   * The browser client executes the full RocketNet client protocol (`STANDARD.md` `[SOURCED: R1]` and `docs/CHANNELS.md` `[SOURCED: R2]`): X25519 ephemeral key generation (`crypto_kx_keypair`), BLAKE2b directional key derivation (`RKTNHNDC`, `RKTNHNDS`, `RKTNSESC`, `RKTNSESS` `[SOURCED: R1, STANDARD.md:989-1134; R7, sdk/rocketnet_keys.cpp]`), ChaCha20-Poly1305 IETF packet sealing/opening (`[SOURCED: R1, STANDARD.md:1285-1399; R7, sdk/rocketnet_protocol.cpp]`), 64-bit sequence number reconstruction, 4096-packet replay protection (`[SOURCED: R1, STANDARD.md:1533-1703; R8, sdk/rocketnet_replay.cpp]`), ack bitfields (`[SOURCED: R1, STANDARD.md:1705-1881]`), and `Packet Type 9` fragmentation (`[SOURCED: R1, STANDARD.md:1883-2000]`).
2. **Strict Connect Token Boundary & Two-Phase Stateless Gateway Admission (`U27`, `U28`, `U29`, `U30`):**
   * The matchmaker delivers the 768-byte Connect Token (`1024-char Base64`) to the browser over an HTTPS `POST` JSON response body (never a URL query string, `U30` `[OPINION]`), alongside a JSON transport descriptor `{ wtUrl, wtCertSha256, webrtcUrl, wsUrl, maxPayloadBytes: 1120 }` (`U36` `[OPINION]`).
   * **Security Invariant (`U27`, `[SOURCED: R1, STANDARD.md:824-893; R6, sdk/rocketnet_connect_token.cpp]`):** Bytes `640..703` of the 768-byte Connect Token hold the plaintext `client_to_server_key` and `server_to_client_key` for the client's local key derivation. **The browser never transmits bytes `640..768` over the network.** The browser only transmits the standard **710-byte `Type 0 Connection Request` packet** (`[SOURCED: R1, STANDARD.md:1204-1225]`).
   * **Stateless Gateway Verification (`U28`, `U29`):** When the gateway receives a browser's first 710-byte `Type 0 Connection Request` (`bytes 0..6` prefilter/type, `6..30` cookie, `30..62` `client_eph_pk`, `62..70` `handshake_salt`, `70..646` `576 B signed connect data`, `646..710` `64 B Ed25519 signature` `[SOURCED: R1, STANDARD.md:1204-1225]`), the gateway:
     1. Checks `version == 0x4E7C1A93`, `expire_timestamp >= now`, and target `server_public_key` / address in bytes `70..159` (`[SOURCED: R1, STANDARD.md:830-866]`);
     2. Verifies the 64-byte `Ed25519` signature (`bytes 646..710`) over the 576-byte `signed connect data` (`bytes 70..646`) using the public `backend_public_key` (`crypto_sign_verify_detached`, zero shared secrets `[SOURCED: R1, STANDARD.md:890-893]`);
     3. Allocates a provisional local UDP socket `udp_fd[i]` (`U29`) and promotes it to an active session socket once the native server responds with `Type 2 Connection Challenge` (`66 B`) / `Type 4 Connection Keep-Alive` (`41 B` min) (`[OPINION]`).
3. **Cookie Exchange & Loopback Cookie Splicing (`U31`, `U32`):**
   * On the wire, `STANDARD.md:1136-1184` (`[SOURCED: R1]`) uses 3 round trips (`Type 0 -> Type 7 Cookie 38B`, `Type 0+Cookie -> Type 2 Challenge 66B`, `Type 3 Response 50B -> Type 4 Keep-Alive 41B`), whereas `CLAUDE.md:71` (`[SOURCED: R5]`) summarizes the post-cookie handshake as an "address-validated two-RTT handshake" (`U32`).
   * Because bytes `6..30` (`return_cookie`) of the 710-byte `Type 0 Connection Request` are unauthenticated cleartext outside the `Ed25519` signature (`[SOURCED: R1, STANDARD.md:1204-1225]`), the co-located gateway can optionally perform RTT 1 (`Type 0` $\rightarrow$ `Type 7` $\rightarrow$ cookie-spliced `Type 0`) against the native server over `127.0.0.1` in `< 150 us` (`U31`), reducing the wide-area browser handshake from **3 WAN RTTs to 2 WAN RTTs** with zero changes to `STANDARD.md` or the native server (`[OPINION]`, evaluated in `E4`).
4. **Solving the 1232-Byte Budget vs. WebTransport `maxDatagramSize` (`U33`, `U34`, `U35`):**
   * Before QUIC Path MTU Discovery (`RFC 8899` `[SOURCED: S78]`) probes past QUIC's 1200-byte initial minimum (`RFC 9000 §14` `[SOURCED: S35]`), `wt.datagrams.maxDatagramSize` can be as low as **`1171 bytes`** (`1200 - 29` `[ESTIMATED]`), which is smaller than RocketNet's default `1232 B` packet ceiling (`1192 B` max unfragmented payload `[SOURCED: R1, R3, sdk/rocketnet.h:420]`).
   * **Merged 3-part protection (`[OPINION]`):**
     1. **Bidirectional `1120 B` Payload Clamp (`U33`, `U35`):** Configure browser sessions (and the server's fragmenter for browser slots, or globally via `max_payload_bytes = 1120`) so `Packet Type 5` and `Packet Type 9` payloads do not exceed `1120 B` (`1153 B` total RocketNet packet $\le 1171\text{ B}$ floor) until PMTUD confirms `maxDatagramSize >= 1250 B`.
     2. **Unidirectional Stream Spillover (`U34`):** If an unmodified native server sends a `1225–1232 B` UDP packet to the gateway while the browser leg's `maxDatagramSize < pkt_len`, the gateway frames that single packet with a 2-byte length prefix over a **one-shot WebTransport unidirectional stream** (`wt.incomingUnidirectionalStreams` `[SOURCED: S1]`), guaranteeing zero silent drops and zero HoL blocking of subsequent datagrams.
5. **What Requires Changes to `STANDARD.md` vs. What Does Not:**
   * **Zero changes to `STANDARD.md` required:** End-to-end AEAD, 710-byte `Type 0` admission, 3-RTT handshake (and loopback cookie splicing), replay protection, `CHANNELS.md` messaging, unidirectional stream spillover, and outer transport migration (`[OPINION]`).
   * **Optional backward-compatible additions if desired later:** Defining a standard TLV inside the Connect Token's 55-byte signed zero-pad (`bytes 521..576` `[SOURCED: R1, STANDARD.md:844, 866]`) or 64-byte trailing zero-pad (`bytes 704..768` `[SOURCED: R1, STANDARD.md:882]`) for `wt_cert_sha256` (`32 B`), `gateway_ports`, and `session_mtu_bytes` (`U36` `[OPINION]`).

### 4.7 Topic 7 — Merged Original Ideas

The strongest original design ideas across `emma`, `aurora`, and `stella` are folded into the architecture and R&D plan:

1. **Happy-Eyeballs Staggered Cascade + Mid-Match Warm Upgrade (`U49`, `emma.md:406-408`, `aurora.md:166`):** Start `WebTransport` at $t = 0\text{ ms}$; if `wt.ready` does not resolve within `200 ms` (or `WebTransport` is undefined), start `WebSocket` (`2 RTTs`) and `WebRTC` (`5 RTTs`) in parallel. Complete the RocketNet handshake immediately over `WebSocket` so the player enters the match without waiting for ICE/DTLS/SCTP, then atomically swap the gateway's active outer transport pointer on the existing local `udp_fd[i]` once the first AEAD-authenticated RocketNet packet arrives over the newly opened `RTCDataChannel` (`tested in E13`).
2. **Gateway-Assisted Loopback Cookie Splicing (`U31`, `emma.md:409-410`, `aurora.md:165`):** Collapse RTT 1 (`Type 0 -> Type 7 Cookie -> Type 0+Cookie`) onto the `< 150 us` localhost hop between the gateway and native server by splicing the 24-byte cookie into bytes `6..30` of the cached 710-byte `Type 0` request (`tested in E4`).
3. **Two-Phase Provisional Gateway Admission on the 710-Byte `Type 0` Request (`U27`–`U29`, `emma.md:173-185`, `stella.md:64, 152`):** Never send bytes `640..768` of the 768-byte Connect Token over the wire; verify the `Ed25519` signature on the 710-byte `Type 0` packet at the gateway using `backend_public_key`, and hold the local UDP mapping in a bounded provisional pool until the native server emits `Type 2` / `Type 4` (`tested in E4, E17`).
4. **Bidirectional `1120 B` MTU Clamp + WebTransport Unidirectional Stream Spillover (`U33`–`U35`, `emma.md:210-212`, `stella.md:153`):** Clamp browser session payloads to `1120 B` (`1153 B` packet $\le 1171\text{ B}$ QUIC floor) and forward any oversized server-to-client packet over a one-shot WebTransport unidirectional stream before PMTUD completes (`tested in E7`).
5. **Single-Threaded Emscripten Mode + `1.5 MiB` Browser Memory Profile (`U37`, `U38`, `emma.md:246-258`, `stella.md:90, 155`):** Guard `rocketnet_platform_thread_create` in `sdk/rocketnet_client_transport.cpp:355-369` under `__EMSCRIPTEN__`, drain `rocketnet_client_receive_packets()` inside `rocketnet_client_transport_update()`, and lower `ROCKETNET_NUM_CLIENT_PACKETS` from `1024` to `128` (`tested in E1, E2`).
6. **Striped Multi-WebSocket ($K=3$) Pool + Outer Queue Shedding (`U13`, `U52`, `emma.md:415-416`, `aurora.md:169`, `stella.md:156`):** Bind $K=3$ parallel `wss://` sockets to the same gateway `udp_fd[i]` and route outgoing ticks to lanes with `bufferedAmount === 0`, letting RocketNet's 4096-packet replay bitmap absorb cross-lane reordering (`tested in E8`).
7. **Seamless Cellular Handoff (`Wi-Fi` $\leftrightarrow$ `5G`) & Mobile `visibilitychange` Grace Window (`U50`, `U51`, `emma.md:421-422`, `aurora.md:167`, `stella.md:50`):** Keep `udp_fd[i]` alive on the gateway across outer QUIC migration or authenticated transport rebinds, and emit synthetic keep-alives during brief mobile tab backgrounding (`tested in E14`).
8. **Shared-Memory Ring / Virtual-Address Driver (`U20`, `emma.md:413-414`, `aurora.md:170`, `stella.md:154`):** If localhost UDP socket overhead ever matters above `2,500` clients/host, couple the gateway to the native server via a lock-free `rocketnet_server_driver_operations_t` shared-memory ring with stable synthetic `rocketnet_address_t` IDs (`tested in E9`).
9. **Zero-Server-CPU Spectator Broadcast & `OPFS` Replays (`U55`, `emma.md:425-426`):** Fan out a single spectator slot from the gateway to thousands of WebTransport spectators and record streams to browser `OPFS` (`tested in E18`).

## 5 Recommendation and layered roadmap

### 5.1 Recommended Architecture (`[OPINION]` Grounded in `[SOURCED]` Facts)

1. **Transports:** Ship a single browser transport abstraction implementing the **3-tier cascade**:
   * **Primary:** `WebTransport` over HTTP/3 (`QUIC DATAGRAM` `[SOURCED: S1, S4, S5]`) with the `createWritable() || writable` normalizer (`[SOURCED: S55]`), `serverCertificateHashes` ($\le 14$-day ECDSA P-256 cert, `allowPooling: false` `[SOURCED: S1 §6.9]`), and `1120 B` initial payload clamp + unidirectional stream spillover (`[OPINION]`).
   * **Secondary UDP Fallback:** `WebRTC RTCDataChannel` (`{ ordered: false, maxRetransmits: 0, negotiated: true, id: 0 }` `[SOURCED: S2, S6, S7]`) connecting to a single-port `ICE-Lite` + `UDP-Mux` gateway (`libdatachannel` or `webrtc-rs` `[SOURCED: S63, S64]`) for iOS/Safari $\le 26.3$ and HTTP/3-blocked networks.
   * **Universal Reach Fallback:** `WebSockets` (`wss://` over TLS 1.3 / TCP port 443 via `uWebSockets` `[SOURCED: S3, S8, S71]`) with `TCP_NODELAY`, `bufferedAmount` shedding, and optional $K=3$ multi-socket striping (`[OPINION]`).
2. **Server Side:** Keep the native C++ `rocketnet` server (`sdk/rocketnet_server_transport.cpp`) **100% unmodified** on its native UDP fast path (`AF_XDP`, `GSO`, `recvmmsg`, `sendmsg_x` `[SOURCED: R4, DRIVERS.md]`). Run a **co-located Browser Gateway process** on the same host that verifies the `Ed25519` signature on the 710-byte `Type 0 Connection Request` using `backend_public_key`, allocates one local UDP socket (`127.0.0.1:port_i`) per browser session (`[SOURCED: R1, STANDARD.md:348]`), and relays raw inner RocketNet ciphertext datagrams verbatim (`[OPINION]`).
3. **Protocol Mapping:** Keep RocketNet's **ChaCha20-Poly1305 IETF AEAD, 64-bit sequence numbers, ack blocks, 4096-packet replay bitmap, and `docs/CHANNELS.md` framing strictly end-to-end** between browser and native server (`[SOURCED: R1, R2]`). Never send bytes `640..768` of the 768-byte Connect Token over the wire (`[SOURCED: R1, R6]`).
4. **Client Library:** Ship **Family A (single-threaded Emscripten WASM build of `sdk/*.cpp` + `sodium/sodium.c`)** first by adding the 8-line `#if !defined(__EMSCRIPTEN__) || defined(__EMSCRIPTEN_PTHREADS__)` receive-poll guard in `sdk/rocketnet_client_transport.cpp:355-369` (`[SOURCED: R5]`), the `ROCKETNET_BROWSER_CLIENT` `1.5 MiB` memory profile, and the `wasm_ring_driver` (`sdk/rocketnet_driver.h:76-119` `[SOURCED: R4]`), packaged inside a Dedicated Web Worker (no `SharedArrayBuffer` or COOP/COEP required `[SOURCED: S27, S59]`).
