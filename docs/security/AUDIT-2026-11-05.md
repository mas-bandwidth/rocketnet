“Closed” means the named receive path refuses the malformed structure before
the described unsafe read/copy/admission. “Caller bounded” identifies a raw
primitive whose bound belongs to its callers. A successful cryptographic open
does not itself validate the decoded grammar. Kernel-owned completion pointers,
lengths and ancillary headers have the posted-buffer OS contract; they are not
packet bytes an unauthenticated peer may supply directly. None of the parsing
rows allocates storage based on a received length/count. Sessions and message
regions use locally sized, preallocated tables/rings; exhaustion drops, defers
or closes as indicated. The map does not assert that all bounded resource use
or every lifetime interleaving has been model checked.

## 2. Packet and token geometry

All datagrams begin with type 1, epoch 1 and filter 4. The prefilter proves the
whole wire extent is 6..1452 before reading them. Types 9..255 are reserved;
client/server direction gates precede type-indexed counters. Session headers
hold 32-bit sequence after the prefilter, then authenticated plaintext and a
16-byte AEAD tag. Only challenge/denied add an explicit 8-byte nonce. Session
plaintext begins with a 7..1027-byte ACK block; its consumed length determines
the remaining type data.

| Type | Direction | Required wire bytes | Parsed body |
|---|---|---|---|
| 0 request | client to server | exactly 710 | cookie 24, salt 8, ephemeral key 32, signed data 576, signature 64 |
| 1 denied | server to client | exactly 34 | sequence 4, nonce 8, tag 16, no plaintext |
| 2 challenge | server to client | exactly 66 | sequence 4, nonce 8, encrypted ephemeral key 32, tag 16 |
| 3 response | client to server | exactly 50 | sequence 4, encrypted zero padding 24, tag 16 |
| 4 keep-alive | both | 41..1452; type data exactly 8 after ACK | client index 32, max clients 32 |
| 5 payload | both | 34..1452; type data 1..1416 after ACK | message form/records or opaque transport payload |
| 6 disconnect | both | 33..1452; no type data after ACK | ACK block only |
| 7 cookie | server to client | exactly 38 | echoed salt 8, opaque expiry 8+MAC 16 |
| 8 ACK | both | 33..1452; no type data after ACK | ACK block only |

There is no separate packet-fragment parser at this base: legacy type 9 is
reserved. Large messages use authenticated message BLOCK records. Their
fragment index/count are uint16; the count is count-minus-one+1, but the local
1 MiB maximum and fragment size 1152 reduce any admitted block to at most 911
fragments. The message reader checks count, fragment, exact nonfinal size,
last-fragment size, window, ring base/span and final aggregate bound before
delivery. No remote fragment count allocates a new array.

The API token is 768 bytes: signed 576, signature 64, clear keys 32+32, zero 64.
Signed fields occupy 521 bytes and have zero 55. The sealed block at signed
offset 89 has 432 bytes and opens to 384: fields 344, zero 40. The server request
carries only signed data and signature, not the outer clear keys/zero 64. The
server verifies the signature before opening the private block and cross-checks
the private protocol/expiry. F2 records the absent zero-tail validation.

### F1 — Low: client GSO receive stages a truncated completion

**Site:** `sdk/rocketnet_client_gso_linux.cpp:408` in
`rocketnet_client_gso_receive_batch`; carry publication is at lines 445–448.
The receive syscall uses `MSG_DONTWAIT` at line 51, not input `MSG_TRUNC`.
It receives into a 64 KiB buffer, so the returned copied length remains bounded.
However, the output `msg_flags & MSG_TRUNC` is not checked before GRO splitting
and staging. An oversized/coalesced input that yields such a kernel completion
can therefore stage incomplete receive data. A no-GRO oversized view is later
rejected by the common wire ceiling; this audit proves neither an out-of-bounds
read nor an authentication bypass, and does not establish which deployed kernel
or GRO configuration can produce this completion from peer traffic.

**Reduction:** reject a completion marked `MSG_TRUNC` before split/carry/copy,
spend the existing bounded skip budget, and preserve valid complete receives.
Use an existing appropriate drop counter if needed. The server equivalent
already rejects this flag at `sdk/rocketnet_server_gso_linux.cpp:868` and
io_uring rejects it at `sdk/rocketnet_uring_codec.h:171`. No new API, flag,
allocation, rate-limit key or transport is needed.

**Benign invariant:** `test_audit_client_gso_truncation_refuses` uses the existing
receive syscall seam to return one zero-filled, full-capacity completion with
the truncation flag. It asserts zero returned records and no carry. It uses no
socket, live server or packet reproducer. The current implementation violates
the first assertion, so the existing expected-failure registry marks this open
finding. When the reduction lands, remove that marker and retain the invariant.
The test also has ordinary valid split/length counterparts in
`test_audit_coalesced_receive_bounds` and the existing GSO unit cases.

### F2 — Low: token readers omit required zero-tail checks

**Sites:** `sdk/rocketnet_connect_token.cpp:28`, `:55`, `:363`, and `:393`;
admission callers are `sdk/rocketnet_client_protocol.cpp:213` and
`sdk/rocketnet_server_protocol.cpp:338`.
`standard/TRANSPORT.md:79` requires receivers to drop a structure whose
`zero[n]` field is nonzero. The token layouts at lines 747, 768 and 803 define
private zero 40, signed zero 55 and outer zero 64. The readers copy only the
meaningful prefix and discard those tails; no subsequent zero-tail predicate
appears on these admission paths. A holder of a valid token can vary the outer
64 bytes without changing the parsed token or authentication material. A token
issuer can supply noncanonical signed/private tails under otherwise valid
signature/seal. This expands admitted encodings contrary to the format; it
does not give an unauthenticated peer signing/sealing keys, additional array
capacity, an out-of-bounds access or a demonstrated authorization bypass.

**Reduction:** check outer bytes 704..767 at client token admission; check signed
bytes 521..575 before admitting the token/request; after successful private open,
check bytes 344..383 before reading/committing private fields. Reuse fixed-size
zero checks and existing failure/status handling, wipe private staging on
failure, and keep fixed field geometry. No SDK change is made in this layer.
The conditional absent-family address fields are also not canonicalized by the
raw token readers; layer 2 should enforce their specified zero requirement in
the same fixed-format validation gate.

**Benign invariant:** `test_audit_token_zero_padding_refuses` changes one outer
reserved byte in the existing frozen token, calls the client protocol's local
connect entry, clears the temporary state and asserts refusal. It never writes
or sends a request. At this base the connect is accepted, so the assertion is
registered as an expected failure. Signed/private padding omission is source
evidence; no issuer-signed malformed network fixture was constructed. Layer 2
should add fixed-buffer zero predicates and ordinary unit cases for each tail,
including all-zero acceptance, first/last nonzero refusal and private staging
wiping; no live network witness is required.

| client terminal (denied/timeout/deadline/disconnect/integrity) | retire I/O keys, wipe secrets, zero state, ack reset | `ClientSession` End; `ClientConnection` KeysErasedWhenDown | Closed |
| server client disconnect | burst none, reset reason CLIENT_DISCONNECTED | `ServerSession` ClientLeaves | Closed |
| server app disconnect | burst, reset reason SERVER_DISCONNECTED | `ServerSession` DisconnectClient | Closed |
| server timeout | reset reason TIMED_OUT | `ServerSession` SlotTimeout | Closed |
| server sweep half-open | mapping removed, claim released | `ServerSession` Deny/Timeout abstraction | Closed |
| slot reuse | every RESET field Init, nothing of the prior session observable | `ClientSession`/`ServerSession` `SlotReuseObservesNothing`, `ResetIsInit` | Closed |

The disconnect burst is sealed before the reset and is the only per-connection
bytes that outlive it; the server's deferred burst carries `client_index = -1`
so it never charges a reused slot.

### 5.5 Replay window

`rocketnet_replay_already_received` refuses below-floor and marked sequences;
`rocketnet_replay_advance` clears skipped bits and the whole ring on a skip of
a full window or more; the server gates the AEAD open and the advance behind
the slot check (`sdk/rocketnet_server_protocol.cpp:1310-1337`).

| Transition | Rule | Model | Verdict |
|---|---|---|---|
| replay check before open | refuse duplicate/too-old before AEAD | `ReplayWindow` AlreadyReceived | Closed |
| advance after open | mark only after successful open | `ReplayWindow` Advance | Closed |
| slot gate before open and advance | no open/advance on a slotless mapping | `ReplayWindow` `NoOpenBeforeConnect`, `NoAdvanceBeforeConnect` | Closed |
| long-skip clears whole ring | skip >= W clears every word | `ReplayWindow` Cleared, `MCReplayWindowBrokenLongSkip` | Closed |
| handshake window | raise-only, never marked | **absent** from `ReplayWindow` (stated at `ReplayWindow.tla:44-49`) | Gap S3 |

### 5.6 Findings (FINDING FORM)

No fail-open transition was found in the audited code: every malformed,
replayed, out-of-order, late, wrong-state or wrong-size packet is refused
before it moves a slot, a mapping, a key or a state, and every disconnect path
resets the per-connection state fail-closed. The three findings below are
model-coverage gaps — transitions the code accepts that the named models do not
carry — and are reported as suspected, unproven by any run of this layer.

**S1 — Low: the standalone ACK (type 8) and, on the server, the payload (type 5)
acceptances are absent from `ClientConnection.tla` / `ServerConnection.tla`.**
Site: `sdk/rocketnet_client_protocol.cpp:1178-1207` (`rocketnet_client_process_ack`)
and `sdk/rocketnet_server_protocol.cpp:1443-1511` (payload/ack delivery). Input:
an authenticated type-8 (or, to the server, type-5) packet. Effect: it refreshes
the idle clock (`last_receive_time`), confirms the slot, and applies its ack
block, so a valid packet of an omitted type keeps a connection alive without
moving its state. What an attacker can do: nothing directly — the packet opens
only under session keys, so an off-path attacker cannot forge one; the omission
is a proof-coverage hole, not a fail-open. Reduction: add `"ack"` (and, in
`ServerConnection`, `"payload"`) to the session packet sets and the
`ClientRecvSession`/`ServerRecvSession` dispatch, as a keep-alive-equivalent
refresh with no state move; pin with a Broken witness that asserts the omitted
type never refreshes the idle clock. `ClientConnection.tla:152` and
`ServerConnection.tla:208` already name the omission.

**S2 — Low: the AEAD integrity-limit teardown transition is absent from the
connection and session models.** Site:
`sdk/rocketnet_client_protocol.cpp:82-93` (`rocketnet_client_integrity_failure`,
state 0) and `sdk/rocketnet_server_protocol.cpp:1142-1173`
(`rocketnet_server_integrity_failure`, slot + mapping removed, reason NONE).
Input: `ROCKETNET_INTEGRITY_LIMIT` (`2^36`, `sdk/rocketnet_constants.h:291`)
sealed packets that fail to open on one connection, across its keys. Effect:
the connection is torn down fail-closed. What an attacker can do: only hasten a
fail-closed teardown of a connection it cannot otherwise enter; it is a defense,
not a weakness. Reduction: add an integrity counter and the teardown transition
to the models at a small limit constant (the production `2^36` cannot be
reached by exhaustive checking), or record the transition as out-of-scope;
`ReplayWindow.tla:204-206` already notes the count is not modelled.

**S3 — Low: the handshake replay window (`handshake_highest_opened`) is
raise-only and is not modelled by `ReplayWindow.tla`.** Site:
`sdk/rocketnet_server_protocol.cpp:1301,1385-1386` (response) and
`sdk/rocketnet_client_protocol.cpp:625,697-698` (challenge/denied), the
reconstruction reference for handshake sequences. Input: a replayed or
far-ahead handshake sequence. Effect: handshake packets are exempt from replay
marking and only raise the high-water mark; the state gates (challenge only in
state 2, denied only in 2/3, response only to an unestablished mapping) prevent
a handshake replay from moving state, so the exemption is not a fail-open, but
the nearest-epoch reconstruction arithmetic for handshake sequences is
unverified by a model. Reduction: extend `ReplayWindow.tla` with a raise-only
handshake window (no mark, high-water advance only) and a witness that a
below-floor handshake sequence is refused, or record the exemption as
out-of-scope. The limitation is stated at `ReplayWindow.tla:44-49`.

Each reduction is a model or documentation change only; no code fix is proposed
because no fail-open transition was identified. If any of these gaps is later
shown to hide a fail-open by a new witness, the fix is surgical and fail-closed,
per the repository's defect-only scope.
